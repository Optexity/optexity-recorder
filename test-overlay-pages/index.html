Recorder blocks interaction — repro

Every control below works when you interact with it in a plain browser (no extension): the green log fires. The customer's bug is that while the CRX recorder is attached and recording, some of these controls go dead — the click/keystroke does nothing and no green line appears.

How to use: (1) open in a normal tab, interact with each — confirm every one logs green. (2) Attach the recorder, start recording, repeat. The cases that produce no green line are the repro.

Mechanism: on click/press/check the recorder swallows your native event and re-performs it via frame.click(selector, {strict:true, timeout:5000}). If that re-perform fails (ambiguous selector, intercepted point, unstable element) the action is silently dropped — so the control never fires. Typing is record-only, but a mismatched active target makes the recorder consume the keystrokes.

0. Control — plain unique button

Baseline. Should fire green both with and without the recorder. If this fails too, the recorder is broken globally, not per-field.

1. Ambiguous selector → strict-mode violation

Two buttons with the same accessible name and no distinguishing attributes. The recorder generates getByRole('button', { name: 'Continue' }), which matches both.

Recorder: strict mode violation: locator resolved to 2 elements → click dropped → button dead. Plain browser: both work.

2. Overlay intercepts the click point

A badge sits over the center of the button (a sibling, not forwarding). By hand you click the visible label area (top-left) and it works. Playwright always clicks the element center.

Recorder: <div class="badge"> intercepts pointer events → click dropped → button dead. Plain browser: clicking the label works.

3. Never-stable (continuously animating) element

The button drifts side to side forever. By hand you can still click it any time.

Recorder: waits for the element to stop moving; it never does → 5s timeout → click dropped → button dead. Plain browser: works.

4. Disabled-looking but clickable via handler

A styled <div role="button"> whose only reliable target is its parent; the recorder may resolve a selector that Playwright can't act on (not the same element, or not hit-testable at center).

Add to cart

Native click bubbles to the handler and fires. Recorder-generated selector / center hit-test can miss on custom widgets.

5. Text field under a focus-forwarding frame (fill blocked)

A transparent frame covers the input and forwards focus on click, so by hand you can type fine. Fill is record-only, so during recording the field is driven by your own keystrokes — but the recorder's active target is the frame, not the input.

Recorder: keystroke target (input) ≠ active model (frame) → keystrokes consumed → can't type. Plain browser: typing works.
